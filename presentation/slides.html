1. Introdução

A compressão de arquivos é fundamental no desenvolvimento de software, administração de sistemas e ciência de dados. Com o crescimento exponencial do volume de dados, a escolha do algoritmo adequado torna-se crítica.

Algoritmos Analisados

gzip (DEFLATE)

LZ77 + Huffman
Alta velocidade, compressão moderada

bzip2 (Burrows-Wheeler)

BWT + MTF + Huffman
Boa compressão, mais lento

xz (LZMA2)

Melhor taxa de compressão
Mais lento de todos

zstd (Zstandard)

Algoritmo moderno (Facebook)
Equilibra velocidade e compressão

Objetivo

Analisar comparativamente os trade-offs entre velocidade e eficiência de compressão para auxiliar na escolha do algoritmo mais adequado em diferentes cenários.

4. Procedimento Experimental

O procedimento de benchmark segue os seguintes passos para cada tamanho de arquivo:

  1. Geração do arquivo de teste: Um arquivo de texto é gerado utilizando o gerador de Cadeias de Markov com o tamanho especificado.
  2. Para cada algoritmo (gzip, bzip2, xz, zstd):
    1. Para cada repetição (3 execuções):
      1. Limpar cache: sync && echo 3 > /proc/sys/vm/drop_caches
      2. Iniciar monitoramento com vmstat e iostat
      3. Executar compressão com perf stat
      4. Medir tamanho do arquivo comprimido
      5. Limpar cache novamente
      6. Executar descompressão com perf stat
      7. Salvar resultados em arquivo CSV
      8. Aguardar 1 segundo (cooldown)

6. Limitações do Estudo

  • Apenas dados textuais (Cadeias de Markov) — não generaliza para binários, imagens ou logs
  • Hardware modesto (i3, 4GB RAM) — comportamento pode variar em outras configurações
  • Uso apenas de níveis padrão de compressão — não reflete cenários com parâmetros ajustados

Recomendações

  • Velocidade máxima: zstd
  • Melhor compressão: xz
  • Uso geral: zstd
  • Compatibilidade: gzip
  • Evitar para uso frequente: bzip2

Conclusão: O algoritmo zstd destaca-se como a melhor escolha para a maioria dos cenários, oferecendo o melhor equilíbrio entre velocidade e eficiência de compressão.
